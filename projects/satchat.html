What it is

A simplified Slack or Discord: one-to-one chats and group channels with live delivery, presence, typing indicators, read receipts, file sharing, GIFs, message search and email alerts. It works on desktop and mobile.

How it's built

  • Separate REST and WebSocket tiers. REST is stateless and easy to scale; socket connections are long-lived and scale differently. Both share one domain codebase.
  • Redis to scale sockets horizontally. Any socket server can emit to a room, and Redis pub/sub relays it to whichever server holds the recipient's connection.
  • Presence that survives many tabs. Each user has a set of live socket IDs in Redis; they go offline only when the last one disconnects, and only that final disconnect writes "last seen" to Postgres.
  • Persist, then broadcast. A message is saved before anyone hears about it, so the database defines the order.
  • Unread counts stored, not counted. Sending increments a counter and opening the chat resets it, so the sidebar never counts rows.
  • Build once, deploy anywhere. The client reads its URLs at container start, so one image runs in every environment.

Shipping it

  • Docker Compose for the full stack locally or on one VM
  • Helm charts per component, with autoscaling for the API, socket, storage and client tiers
  • Jenkins pipelines that build and push images, then deploy to a VM or a Kubernetes cluster provisioned with Terraform
  • /health and /ready checks on every service, Nginx with SSL in front
